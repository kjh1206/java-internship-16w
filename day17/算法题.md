## 题目一：快乐数（LeetCode 202，简单）

**题目**：编写一个算法来判断一个数 `n` 是不是快乐数。

「快乐数」定义为：

- 对于一个正整数，每一次将该数替换为它每个位置上的数字的平方和。
- 然后重复这个过程直到这个数变为 1，也可能是**无限循环**但始终变不到 1。
- 如果这个过程**结果为 1**，那么这个数就是快乐数。

如果 `n` 是快乐数就返回 `true`；不是，则返回 `false`。

**示例**

```
输入：n = 19
输出：true
解释：
1² + 9² = 82
8² + 2² = 68
6² + 8² = 100
1² + 0² + 0² = 1     ← 到达 1，快乐

输入：n = 2
输出：false
```

**提示**

- `1 <= n <= 2³¹ - 1`

**题眼（先自己想 10 分钟再看）**

<details>
<summary>点开看思路</summary>

两种写法，本质都是"检测循环"：

1. **哈希集合**：把每次算出的数丢进 `Set`，如果某次发现已经出现过 → 说明进入循环 → 不是快乐数。空间 O(log n)。
2. **快慢指针（Floyd 判环）**：把"n → 各位平方和"看成链表上的 next 指针，那就是 141 环形链表。快指针走两步、慢指针走一步，相遇就说明有环。空间 O(1)。

写 `int digitSquareSum(int n)` 这个辅助方法，注意 `while (n > 0) { int d = n % 10; sum += d * d; n /= 10; }`。

</details>

**要求**

- 两种写法都实现，比较空间复杂度
- 自己测：19、1、2、7、4

## 题目二：存在重复元素 II（LeetCode 219，简单）

**题目**：给你一个整数数组 `nums` 和一个整数 `k`，判断数组中是否存在**两个不同的索引** `i` 和 `j`，满足 `nums[i] == nums[j]` 且 `abs(i - j) <= k`。

**示例**

```
输入：nums = [1,2,3,1], k = 3
输出：true
解释：nums[0] 和 nums[3] 相等，距离 3 ≤ k

输入：nums = [1,0,1,1], k = 1
输出：true
解释：nums[2] 和 nums[3] 相等，距离 1 ≤ k

输入：nums = [1,2,3,1,2,3], k = 2
输出：false
```

**题眼（先自己想 10 分钟再看）**

<details>
<summary>点开看思路</summary>

**滑动窗口 + 哈希表**：

- 维护一个"最近 k 个元素"的窗口，窗口用 `HashSet` 存
- 遍历到 `nums[i]` 时：
  - 如果 `set` 里已经有它 → 返回 true（说明窗口内存在相同元素，距离一定 ≤ k）
  - 否则把它加进 `set`
  - 如果 `set.size() > k` → 把 `nums[i - k]` 移出窗口
- 时间复杂度 O(n)，空间 O(min(n, k))

对比暴力：对每个 i 检查前 k 个 → O(n·k)，k 大时会超时。

</details>

**要求**

- 先写暴力版（O(n·k)），再写滑动窗口版，两个都跑通
- 测：`[1,2,3,1],3` → true；`[1,0,1,1],1` → true；`[1,2,3,1,2,3],2` → false；`[1],0` → false
