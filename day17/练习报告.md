## 题一：括号匹配（ArrayDeque 栈）

**文件**：`BracketCheck.java`，11/11 通过

```
()  ()[]{}  {[]}  {[()]}  ""           → true
(]  ([)]  (  )  (((((  ){              → false
```

**要点**：
- 用 `ArrayDeque` 当栈，不用 `Stack`（`Stack` 是同步的、已过时）
- 三种非法：多余右括号（栈空还要 pop）、类型不匹配、遍历完栈非空
- 空串返回 true —— 这是"合法"的边界，容易被漏掉

## 题二：手写双向链表

**文件**：`MyLinkedList.java`（Node 双向 / addFirst / addLast / removeFirst / get / size）

```
正向遍历： [a, b, c]
反向遍历： [c, b, a]
空表 removeFirst → NoSuchElementException
get(99)         → IndexOutOfBoundsException
交替插入 1..6：   [5, 3, 1, 2, 4, 6]
反向：           [6, 4, 2, 1, 3, 5]
```

**关键实现**：`node(index)` 按下标折半选方向

```java
if (index < size >> 1) { 从头往后走 }
else                   { 从尾往前走 }
```

这是 JDK `LinkedList.node()` 的真实做法，把最坏情况从 n 降到 n/2。

**踩坑**：`removeFirst` 在空表上要抛 `NoSuchElementException`（不是返回 null），`get` 越界抛 `IndexOutOfBoundsException`——两个异常类型不能混。

## 题三：三种逆序打印方式

**文件**：`DescIterDemo.java`

- `ListIterator.previous()`（从末尾开始）
- `descendingIterator()`（`Deque` 接口，`LinkedList` 支持）
- `get(i)` 倒着遍历

三者输出一致。性能对比（2 万元素求和）：

```
get(i) 倒序        : 116.9 ms
descendingIterator :   1.25 ms      ← 94 倍
```

## 题四：求和，get(i) vs for-each

**文件**：`SumBench.java`（1 万元素）

```
get(i)     : 28.779 ms（2877.9 ns/元素）
for-each   :  0.439 ms（  43.9 ns/元素）
```

**结论**：`LinkedList.get(i)` 每次从头/尾走 i/2 步 → 整体 O(n²)。**任何按下标循环访问 LinkedList 的代码都是 bug 温床**，必须用迭代器或 for-each。

## 题五：内存估算

**文件**：`MemoryEstimate.java`（`-Xmx512m`，用 `Runtime` 前后差估算）

```
new Object[1000000]        : +4.0 MB   （100 万 × 4B 引用 + 数组头）
new LinkedList<>()         : +0.000 MB （空壳只有 first/last/size）
空链表 add 100 万个 Integer : +39.0 MB  （每 Node ≈32B + Integer 对象）
```

| 结构 | 100 万元素内存 | 随机访问 | 头插 |
|---|---|---|---|
| ArrayList | 4 MB（引用）+ 扩容余量 | O(1) | O(n) |
| LinkedList | ≈39 MB | O(n) | O(1) |

**结论**：ArrayList 用"连续格子"换随机访问；LinkedList 每个元素付 ~32B 房租（三个引用 + 对象头）换头尾 O(1)。**绝大多数场景选 ArrayList**。
