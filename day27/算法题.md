## 题一：LC 146 LRU 缓存（中等 · 高频面试题）

### 题目

实现一个 LRU（最近最少使用）缓存，支持两个操作，都要求 **O(1)** 时间：

- `get(key)`：如果 key 存在，返回 value 并把该 key 标记为"最近使用"；否则返回 `-1`
- `put(key, value)`：key 存在则更新 value 并标记最近使用；不存在则插入。若插入后容量超限，**淘汰最久未使用的 key**

### 示例

```
输入:
["LRUCache","put","put","get","put","get","put","get","get","get"]
[[2],[1,1],[2,2],[1],[3,3],[2],[4,4],[1],[3],[4]]

输出:
[null,null,null,1,null,-1,null,-1,3,4]

过程（容量 2）:
put(1,1)  -> {1=1}
put(2,2)  -> {1=1, 2=2}
get(1)    -> 1，1 变成最近使用，顺序变为 [2, 1]
put(3,3)  -> 超容量，淘汰最久未用的 2 -> {1=1, 3=3}
get(2)    -> -1
put(4,4)  -> 淘汰 1 -> {3=3, 4=4}
get(1)    -> -1
get(3)    -> 3
get(4)    -> 4
```

### 提示

- 需要"快速查找"（O(1)）→ 哈希表
- 需要"快速调整顺序 + 快速删除头尾"（O(1)）→ **双向链表**
- 两者合起来就是 `LinkedHashMap(accessOrder=true)` 的内部结构
- 只用 `LinkedHashMap` 写出来的答案**面试会追问"不许用 JDK 现成的"**，所以必须先手写双向链表版

### 题眼（卡住再看）

1. 结构：`HashMap<Integer, Node>` + 双向链表（`head`/`tail` 哨兵），`Node` 存 `key/value/prev/next`
2. 访问或写入后：把节点**移到链表尾部**（尾 = 最近使用，头 = 最久未用）
3. 超容量时：删 `head.next`，并且**别忘了从 Map 里也删掉它的 key**（这是最容易漏的一步）
4. 所有"移动"操作都是"先摘下来、再挂到尾部"，写个 `removeNode` + `addLast` 两个私有方法就够了

### 要求

- `get` 和 `put` 都必须 O(1)
- 不用 `LinkedHashMap`（先手写）；写完可以再用 `LinkedHashMap` 写 15 行版做对照
- 边界：容量 1、反复 put 同一个 key、get 不存在的 key

### 验收

- [ ] 上面示例输出完全一致
- [ ] 容量 1 时连续 put 两个 key，第一个被淘汰
- [ ] 能口述"为什么必须双向链表"（单链表删尾需要前驱，O(n)）

## 题二：LC 706 设计哈希映射（简单）

### 题目

不使用任何内建的哈希表库，设计一个哈希映射，支持：

- `put(key, value)`：插入或更新
- `get(key)`：不存在返回 `-1`
- `remove(key)`：不存在则什么都不做

所有 key/value 范围 `0 <= key, value <= 10^6`，操作次数最多 `10^4`。

### 示例

```
输入:
["MyHashMap","put","put","get","get","put","get","remove","get"]
[[],[1,1],[2,2],[1],[3],[2,1],[2],[2],[2]]

输出:
[null,null,null,1,-1,null,1,null,-1]
```

### 提示

- 最直白的做法：`int[] data = new int[1000001]`，初始化为 `-1`。**能过，但面试官会问"key 范围是 10^9 怎么办"**
- 正经做法：**数组 + 链表（拉链法）**，和你今天手写的 `SimpleHashMap` 是同一个东西
- 哈希函数可以简单点：`key % 769`（769 是质数，取模后分布均匀）

### 题眼（卡住再看）

1. `bucket[i]` 存的是一个链表（`List<int[]>` 或自己的 Node），每个节点是 `[key, value]`
2. `put`：找到 `key % 769` 的桶，遍历链表，有相同 key 就改 value，没有就头插
3. `get` / `remove` 同理
4. **用质数做桶数**：如果桶数是 10 的倍数，所有 key 末位相同的会挤在一起

### 要求

- 不能用 `HashMap` / `Hashtable` / `HashSet`
- 桶数取 769（质数）
- 负载过高时可以扩容（可选加分项）

### 验收

- [ ] 示例输出一致
- [ ] `put` 同一个 key 两次，`get` 返回后一次的 value
- [ ] `remove` 不存在的 key 不抛异常
- [ ] 能解释"为什么桶数用质数而不是 1000"
