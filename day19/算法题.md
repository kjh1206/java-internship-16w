## 题一：49. 字母异位词分组（中等）

**链接**：https://leetcode.cn/problems/group-anagrams/

### 题目

给你一个字符串数组 `strs`，请你将**字母异位词**组合在一起。
可以按任意顺序返回结果列表。

> 字母异位词：由重新排列源单词的所有字母得到的一个新单词（字母种类和次数都相同）。

**示例 1**

```
输入: strs = ["eat", "tea", "tan", "ate", "nat", "bat"]
输出: [["bat"],["nat","tan"],["ate","eat","tea"]]
```

**示例 2**

```
输入: strs = [""]
输出: [[""]]
```

**示例 3**

```
输入: strs = ["a"]
输出: [["a"]]
```

**约束**

- `1 <= strs.length <= 10^4`
- `0 <= strs[i].length <= 100`
- `strs[i]` 仅包含小写英文字母

### 题眼

字母异位词的**共同点**是"排序后完全相同"，或者"26 个字母的计数完全相同"。
→ 把"排序后的串"或"计数数组"当作 **HashMap 的 key**，value 是同一组的字符串列表。

**为什么不能直接用原串做 key**：`eat` 和 `tea` 是两个不同的 key，但它们该分到一组。

### 两种 key 的取舍

| 做法 | 构造 key 的代价 | 适用 |
|---|---|---|
| 排序后作 key：`char[] c = s.toCharArray(); Arrays.sort(c); new String(c)` | O(k log k) | 短串、写法最短 |
| 计数作 key：`int[26]` 转成字符串 / `Arrays.toString(cnt)` | O(k) | 长串、字符集小 |

> 进阶：也可以把 `int[26]` 用 `Arrays.hashCode` 或 `StringBuilder` 拼成 `"1#0#2#..."` 当 key。

### 要求

1. 用"排序作 key"写一版，再用"计数作 key"写一版；
2. 自己写测试：至少覆盖示例 1、示例 2、`["",""]`、`["ab","ba","abc"]`；
3. 打印时**对每组的元素排序后再打印**，否则输出顺序不稳定，肉眼比对困难。

### 验收

- [ ] 两版都能 AC
- [ ] 能说出"排序作 key"的时间复杂度是 O(n·k log k)，"计数作 key"是 O(n·k)
- [ ] 能解释为什么 value 要用 `List<String>` 而不是 `Set<String>`

## 题二：350. 两个数组的交集 II（简单）

**链接**：https://leetcode.cn/problems/intersection-of-two-arrays-ii/

### 题目

给你两个整数数组 `nums1` 和 `nums2`，请你以数组形式返回两数组的交集。
返回结果中每个元素出现的次数，应与元素在两个数组中都出现的次数一致
（**取较小值**）。可以不考虑输出结果的顺序。

**示例 1**

```
输入: nums1 = [1,2,2,1], nums2 = [2,2]
输出: [2,2]
```

**示例 2**

```
输入: nums1 = [4,9,5], nums2 = [9,4,9,8,4]
输出: [4,9]  或 [9,4]
```

**约束**

- `1 <= nums1.length, nums2.length <= 1000`
- `0 <= nums1[i], nums2[i] <= 1000`

### 题眼

"每个元素取较小次数" = **计数器取 min**。
→ 先用 HashMap 统计 `nums1` 的每个数出现次数，再遍历 `nums2`，遇到就减 1，减到 0 就跳过。

### 三个层次（面试会追问）

1. **哈希计数**：O(m+n) 时间、O(min(m,n)) 空间。
   小技巧：**统计较短的数组**，空间更省。
2. **排序 + 双指针**：O(m log m + n log n) 时间、O(1) 额外空间。
   有序时双指针更快，且答案天然有序。
3. **值域计数（本题可用）**：因为 `0 <= nums[i] <= 1000`，直接开 `int[1001]` 计数，
   O(m+n) 时间、O(1001) 空间，比 HashMap 更快（没有装箱和哈希计算）。

### 要求

1. 先写哈希版（并保证统计的是较短的那个数组）；
2. 再写双指针版（自己先把两个数组排序）；
3. 用 `[4,9,5]` 与 `[9,4,9,8,4]` 对比两版输出，并解释为什么结果顺序可以不同。

### 验收

- [ ] 两版都能 AC
- [ ] 能说出"为什么统计短数组"能省空间
- [ ] 能说出双指针版需要额外排序、但空间是 O(1)
- [ ] 能答出"如果数组已有序，选哪个版本"

## 一句话带走

> 哈希题的通用套路：**先问"我要拿什么当 key"，再问"value 存什么"**。
> 想清楚这两个问题，O(n²) 就变成 O(n)。
