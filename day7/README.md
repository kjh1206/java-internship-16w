# 记账本（控制台版）

Java 学习第 1 周的练手项目：一个纯控制台的收支记录本，没有数据库、没有框架、没有第三方库，全部逻辑写在一个 197 行的 `Main.java` 里。

做它的目的不是"做出一个记账本"，而是把 **数组 + 方法 + 循环 + switch + Scanner + 输入校验** 一次性练到能用。

## 功能

| 菜单 | 功能 | 实现要点 |
|:---:|---|---|
| 1 | 添加一笔 | 日期 / 类型 / 金额三段 `while` 校验，输错重输 |
| 2 | 查看全部 | 五个平行数组按下标同步读取 |
| 3 | 按类型筛选 | 传 1 看收入，传 2 看支出 |
| 4 | 统计总结余 | 收入 − 支出 |
| 5 | 退出 | 改循环标志位 |
| 6 | 删除最后一笔 | `i--` 并把该位数据清空 |
| 7 | 按金额排序 | 手写选择排序，五个数组同步交换 |

## 怎么运行

环境：JDK 17 及以上（我用 JDK 21）。

```bash
# 数组版
javac -encoding UTF-8 -d out src/Main.java
java -cp out Main

# 对象版
javac -encoding UTF-8 -d out src/Main2.java
java -cp out Main2
```

`-encoding UTF-8` 不能省，源码里有中文，Windows 默认 GBK 会报"非法字符"。

## 数据是怎么存的

五个长度 100 的数组，**同一个下标 `i` 描述同一笔记录**：

```java
static int[]    xuhao = new int[100];     // 序号
static String[] data  = new String[100];  // 日期 "11-08"
static int[]    type  = new int[100];     // 1 收入 / 2 支出
static double[] count = new double[100];  // 金额
static String[] nots  = new String[100];  // 备注
static int i = 0;                         // 当前笔数，也是下一个空位的下标
```

这就是"平行数组"：没有对象，所有字段拆成五个数组，靠下标对齐。**排序时五个数组必须一起交换**，漏一个就全乱——这正是它容易出错、也正是它值得写一遍的原因。

## 输入校验：三层

一笔记录要过三关，任何一关不过就重输：

1. **形状**：长度 5、第 3 位是 `-`、其余四个字符都是数字
2. **真假**：月份 1–12，日期不超过当月天数（`02-30` 要拦住）
3. **业务**：金额 > 0，类型只能是 1 或 2

第 1 关用 `charAt` + `Character.isDigit`，第 2 关查月天数表 `{0,31,28,...}`，第 3 关是普通的 `if`。三层都过才写入数组。

## 已知限制

- **数据不保存**，退出即丢（下一步学文件 IO + 序列化）
- 最多 100 笔，写死
- 序号 `xuhao` 其实是冗余的：下标 + 1 就能算出来，但现在已经用在输出里，想删要一起改 `showAll()`
- 菜单和"按类型筛选"用 `nextInt()` 读，输入字母会抛 `InputMismatchException`
- 菜单 4 的标题写的是"统计总支出"，实际显示的是结余（`case 4` 里那句 `println` 漏改了）
- 金额用 `double`，`0.1 + 0.2` 这类精度问题在真实记账里不能接受（应该用整数分或 `BigDecimal`）

## 从数组版到对象版

`Main2.java` 是同一功能的第二版：把五个平行数组换成一个 `Record` 对象数组。

```java
records[i] = new Record(date, type, amount, note);   // 一行代替五次赋值
records[i].setCount(35.0);                           // 改一个字段，不用管下标
```

对比下来最直接的收益：**排序只需要交换 `records[i]` 和 `records[j]` 两个引用**，不用再同步五个数组。这就是"对象"存在的理由——把散落的相关数据捆成一个整体。

## 学到的东西

- 五个平行数组必须同步交换，一处漏改就错位 → 理解了封装的价值
- `count`（当前笔数）≠ 数组 `length`（容量），删除时两个都要动手
- 所有输入都要校验：写的时候觉得麻烦，跑起来一个字母就崩
- `Scanner` 混用 `nextInt()` 和 `nextLine()` 会留换行符，必须手动 `nextLine()` 消费
